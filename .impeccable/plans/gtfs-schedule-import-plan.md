# Implementation Plan: GTFS Schedule Import (derived, not raw)

## Overview
Import Transjakarta GTFS schedules in derived form only: per-line segment travel times + operating windows feed the journey planner's ETA math and bound the departure board, replacing flat `distance × factor` estimates. No raw `stop_times` ship in the repo; GTFS times are headway templates (`exact_times=0`), so the product never displays them as exact departures.

## Architecture Decisions
- **Derived artifact, not raw GTFS**: a committed `src/lib/data/gtfs-derived.json` (per line+direction: ordered stop ids, median segment seconds, first/last trip per day-class, headway) generated by an offline script from the official feed. Reviewable diffs, deterministic builds, ~1.3MB raw collapses to ~100–200KB derived.
- **Fetch at generation time, never vendored**: script downloads `https://gtfs.transjakarta.co.id/files/file_gtfs.zip` on demand; the zip itself is never committed.
- **Bus lines only**: GTFS covers bus. Rail keeps current flat-factor math via an explicit fallback path (tested).
- **Headways stay hand-authored**: GTFS frequencies validate but do not overwrite `headwayMinutes` (avoids silent behavior change; validator reports drift instead).
- **Honesty preserved**: departures remain headway projections (same semantics as today), just more of them and clipped to the real operating window. No fake exact times.
- **Attribution**: in-app credit line ("Data jadwal: PT Transportasi Jakarta" + 5 translations) wherever schedules surface; quarterly re-pull documented as ops practice, not automated.

## Risks and Mitigations
| Risk | Impact | Mitigation |
|------|--------|------------|
| GTFS feed changes shape/IDs between pulls | Medium — derivation breaks or silently shifts | Validator fails loudly on schema drift; stop-id remaps surface as count diffs in review |
| Segment medians mislead on highly variable routes | Low — ETA is an estimate either way | Keep fallback; assert bands, not exact values, in tests |
| Operating-window edge cases (AMARI overnight, single-day X service) | Low | Explicit service allowlist; overnight handled as first-trip-next-day, tested |
| Scope creep into admin timetable UI | Medium | Explicitly out of scope: no admin UI changes in this plan |
